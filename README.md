# MSX Channels

Зацикленные HLS-каналы для Media Station X из вашей видеотеки. Один Docker Compose,
одна подключённая папка и один домен или IP. Админка позволяет загрузить видео,
создать канал, выбрать ролик и заменить его прямо во время просмотра.

## Быстрый запуск

```bash
git clone https://github.com/dexogen/msx-channels.git
cd msx-channels
mkdir -p videos
cp .env.example .env
```

В `.env` задайте `ADMIN_PASSWORD` длиной не менее 12 символов. Файл `.env` не
должен попадать в Git; права `0600` рекомендуются. Пароль используется только
для админки, воспроизведение в MSX не требует входа.

На Linux подключённая папка должна быть доступна контейнерному UID/GID `10001`
для чтения и записи. Для новой пустой папки:

```bash
sudo chown 10001:10001 ./videos
chmod 600 .env
docker compose pull
docker compose up -d
```

Существующей папке с видео предоставьте аналогичные права без изменения прав
на посторонние данные. На Docker Desktop bind mount обслуживается средствами
Docker Desktop. Путь можно изменить через `VIDEO_DIR=/absolute/path/to/videos`.

- Админка: `http://SERVER_IP:8080/admin`, логин `admin`, пароль из `.env`.
- Страница каналов: `http://SERVER_IP:8080/`.
- Общий M3U: `http://SERVER_IP:8080/channels.m3u`.

Загрузите ролики через админку или скопируйте их в `videos/`. Затем нажмите
«Создать канал», задайте название и выберите файл. Сами файлы становятся
видеотекой; каналы создаются вручную. Один ролик может использоваться несколькими
каналами, в том числе с разным поворотом.

## Настройка Media Station X

Откройте **Settings → Start Parameter → Setup** и введите `SERVER_IP:8080`.
Приложение запросит `/msx/start.json` и покажет общее меню каналов.

Для HTTPS за reverse proxy установите, например:

```dotenv
PUBLIC_URL=https://video.example.com
```

Proxy должен направлять запросы на порт `8080` контейнера. В MSX введите
`video.example.com` и включите замок HTTPS. Все HLS-ссылки, миниатюры и JSON
используют один адрес; дополнительные поддомены не нужны. Если `PUBLIC_URL`
пустой, адрес определяется по HTTP Host и `X-Forwarded-Proto`. Для постоянного
размещения за proxy лучше задавать `PUBLIC_URL` явно.

Для загрузки больших файлов настройте лимит и таймаут reverse proxy. Пример
дополнительной конфигурации nginx/Nginx Proxy Manager для лимита приложения 2 GiB:

```nginx
client_max_body_size 2050m;
client_body_timeout 3600s;
proxy_read_timeout 3600s;
proxy_request_buffering off;
```

HTTPS рекомендуется для админки. Просмотр доступен без авторизации и предназначен
для доверенной сети. Если публикуете сервис в интернете, учитывайте, что каналы
и подготовленные видеосегменты доступны всем, кто знает адрес.

## Замена видео без настройки телевизора

В карточке канала нажмите «Изменить», выберите другой ролик и сохраните.
`/hls/CHANNEL_ID/index.m3u8` остаётся прежним, ID и нумерация HLS-сегментов
сохраняются. Сервер сначала готовит новое видео и только затем добавляет его
сегменты в текущий эфир. При ошибке подготовки старый ролик продолжает играть.

Уже отправленные плееру сегменты не меняются. Переключение обычно видно через
несколько секунд после подготовки; задержка зависит от буфера телевизора.
На границе используется стандартный `EXT-X-DISCONTINUITY`. Повторно открывать
канал или менять Start Parameter не требуется. Возможность абсолютно незаметного
перехода между разными разрешениями зависит от плеера WebOS; для наиболее ровного
перехода используйте одинаковые разрешение, пропорции и громкость роликов.

Чтобы увидеть **новый** канал или новое название, обновите меню MSX. Это не
требуется при замене видео уже открытого канала. Удаление канала останавливает
его вещание. Удаление и повторное создание создаёт новый ID: для замены ролика
используйте редактирование существующего канала.

## Форматы видео

Предпочтительный вход: **MP4, H.264, SDR, со звуком AAC или без звука**.
Поддерживаемые расширения: `.mp4`, `.m4v`, `.mov`, `.mkv`, `.webm`, `.avi`,
`.ts`, `.m2ts`, `.mpg`, `.mpeg`. Фактическая возможность чтения зависит от
декодеров FFmpeg внутри образа. H.264, HEVC SDR, VP8/VP9, AV1 SDR, ProRes
и MJPEG декодируются стандартной сборкой FFmpeg из Debian.

- MOV/ProRes с прозрачностью сводится на чёрный фон.
- Сохраняется первая звуковая дорожка. При её отсутствии добавляется тишина.
- HDR/PQ/HLG намеренно отклоняется: сначала преобразуйте ролик в SDR. Тональное
  преобразование автоматически не выполняется.
- DRM, внешние URL, аудиофайлы без видео и внешние плейлисты не поддерживаются.
- Вложенные каталоги читаются. Скрытые файлы и символические ссылки пропускаются.
- Для копирования вне админки лучше сначала записать временный файл и атомарно
  переименовать его. Сервис ждёт стабильного размера/mtime перед подготовкой.

На выходе: MPEG-TS HLS, H.264 High/yuv420p, AAC stereo 48 kHz, 30 fps по
умолчанию; до `1920×1080` или `1080×1920`, без увеличения исходного размера.
Повороты `0/90/180/270°` выбираются отдельно для каждого канала.

## Загрузка и удаление

Админка адаптирована к телефону: карточки в одну колонку, крупные кнопки,
полноширинные формы и индикатор загрузки. Можно выбрать несколько файлов;
они загружаются по очереди. По умолчанию лимит — 2 GiB на файл.

Файл появляется в видеотеке только после завершения загрузки. Существующий файл
с тем же именем не перезаписывается. Ошибка подготовки отображается рядом с
файлом и не останавливает остальные каналы.

Удаление видео удаляет **исходный файл из подключённой папки**. Файл, выбранный
хотя бы в одном канале или ещё проигрывающийся во время переключения, удалить
нельзя. Сначала смените видео в каналах или удалите каналы. Это ограничение
относится к админке; не удаляйте используемые файлы вручную на хосте.

## Хранение и нагрузка

- `/media` — подключённая папка исходников, read/write для загрузки и удаления.
- `/data/channels.sqlite3` — каналы и их постоянные ID.
- `/data/cache` — подготовленные HLS-сегменты и миниатюры, кэш по SHA-256
  содержимого и параметрам обработки.
- Сессии админки хранятся в памяти и сбрасываются при перезапуске.

FFmpeg работает только при подготовке нового файла/варианта. В эфире сервер
двигает небольшое HLS-окно над готовыми сегментами, поэтому постоянного кодирования
и отдельного процесса на каждый канал нет. Разные зрители видят общую временную
шкалу одного канала. Подготовка по умолчанию выполняется последовательно, в два
потока CPU. Кэш сокращает время последующих запусков.

Кэш сохраняется при удалении исходников: старые сегменты ещё могут находиться в
буфере телевизора. Следите за свободным местом. Для полной пересборки кэша можно
остановить сервис и очистить **только `/data/cache`**, сохранив SQLite. Не удаляйте
volume `cache`, если хотите сохранить ID каналов. Один экземпляр сервиса должен
владеть своим `/data`; совместное использование volume несколькими репликами не
поддерживается. После перезапуска URL сохраняются, но временная шкала эфира
начинается заново; требуется обычное восстановление соединения плеером.

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `VIDEO_DIR` | `./videos` | Папка на Docker-хосте |
| `HTTP_PORT` | `8080` | Порт на Docker-хосте |
| `PUBLIC_URL` | автоматически | Внешний HTTP(S) origin, без path |
| `ADMIN_USER` | `admin` | Логин админки |
| `ADMIN_PASSWORD` | обязательно | Пароль, минимум 12 символов |
| `MAX_UPLOAD_BYTES` | `2147483648` | Лимит загрузки одного файла |
| `OUTPUT_FPS` | `30` | FPS подготовленного видео, 1–60 |
| `CRF` | `20` | Качество H.264, меньше — лучше и больше размер |
| `FFMPEG_THREADS` | `2` | Потоки CPU при подготовке |
| `PREPARE_JOBS` | `1` | Число параллельно готовящихся файлов |
| `MSX_IMAGE` | `ghcr.io/dexogen/msx-channels:latest` | Образ или закреплённый digest |

Прямые env контейнера `SCAN_INTERVAL` и `SETTLE_SECONDS` по умолчанию равны `5`;
их можно добавить в `environment` при необходимости.

## Обновление и диагностика

```bash
docker compose pull
docker compose up -d
docker compose logs -f --tail=100
```

`/healthz` проверяет фоновые задачи сервера; `/readyz` возвращает `200`, когда
есть хотя бы один готовый канал, иначе `503`. Пустая видеотека — допустимое
состояние: контейнер остаётся healthy. Ошибки роликов видны в админке.

Для резервной копии остановите сервис и сохраните `/data` вместе с исходниками
`/media`. Для отката версии укажите старый `MSX_IMAGE` и выполните
`docker compose up -d`. Не используйте `down -v` для обычного обновления.

## Сборка и проверка

```bash
docker compose -f compose.yaml -f compose.build.yaml up -d --build
```

Для тестов локально нужны Python 3.12+ и FFmpeg:

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt pytest
.venv/bin/python -m pytest -q
```

GitHub Actions запускает тесты и публикует `linux/amd64` образ в GHCR после push
в `main`, по тегам `v*` и вручную. Теги образа: `latest`, `sha-...`, версия из
Git tag. Pull requests проходят тесты без публикации. Actions используют
`GITHUB_TOKEN` с `packages: write`; отдельный registry token не нужен.
Для анонимного `docker pull` пакет GHCR должен иметь visibility `Public`.

Проверяются постоянство ID, нумерация/границы HLS, реальное переключение красного
видео на синее в уже открытом FFmpeg-плеере, поворот, сохранение каналов после
restart и изоляция повреждённых файлов.
